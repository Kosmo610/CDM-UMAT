# RVE 메시 (TexGen 출력)

`assemble_inp.py` 의 입력입니다. **세 파일은 한 세트이며 따로 쓰면 안 됩니다.**

| 파일 | 내용 |
|---|---|
| `CSiC_RVE_0135.inp` | 메시 + ElSet + 주기경계조건(`*Equation` 57식) + 드라이버 |
| `CSiC_RVE_0135.ori` | **요소별** 섬유 방향 2벡터. 업로드는 `.txt`였고 확장자만 되돌림 |
| `CSiC_RVE_0135.eld` | 요소별 얀 인덱스 / 얀 중심선 상대좌표 / 체적분율 / 얀 표면까지 거리 |

## 검증 완료 (2026-07-28, 솔버 없이)

| 항목 | 값 |
|---|---|
| TexGen 설정 | 0.135 mm |
| 요소 / 노드 | **26,452 C3D4** / 5,686 |
| RVE 치수 | 3.5 × 3.5 × 0.44 mm, V = **5.39 mm³**, 충전율 100 % |
| ElSet | Matrix(15,369) + Yarn0(2,745) / Yarn1(2,811) / Yarn2(2,763) / Yarn3(2,764) |
| **섬유체적비** | 얀 0.4982 × Vf_yarn 0.79194 = **39.46 %** (카드 39.6 %, Zhang "약 40 %") |
| `.ori` 행 수 | 26,452 라벨행 + 기본행 1 = **요소 수와 정확히 일치**, 라벨 1..26452 연속 |
| 방향 누락 요소 | **0개** |
| 얀 방향 | Yarn0/1 = (0.993, 0, ±0.008) **warp∥x** · Yarn2/3 = (0, 0.993, ±0.004) **weft∥y** |
| 매트릭스 방향 | 100 % 단위행렬 (등방성이라 정상) |
| 드라이버 매핑 | `0=e_x 1=e_y 2=e_z 3=e_xy 4=e_xz 5=e_yz` → `--shear-order xy-xz-yz` |
| PBC 식 형태 | `FaceA − FaceB − Lx·U_d0 = 0` → **U(드라이버) = 거시 변형률** |

평균 방향벡터 크기가 0.993(<1)인 것은 얀이 **굴곡(crimp)** 진다는 뜻으로, 평직에서 정상입니다.

## 덱 생성

```bash
python3 abaqus/assemble_inp.py abaqus/meshes/CSiC_RVE_0135.inp \
        --inline-ori --model v2 --prefix ZHANG2022_c26k
```

`--inline-ori` 로 `.ori` 가 덱 안에 들어가 **자기완결** 파일이 됩니다.

## ⚠️ 새 메시를 뽑으면

`.ori` 는 **요소별**이므로 메시와 한 몸입니다. 새 메시에 옛 `.ori` 를 쓰면
**에러 없이 섬유 방향이 틀린 채로 수렴합니다.** 항상 쌍으로 새로 뽑고,
위 검증표(특히 **섬유체적비**와 **얀 평균 방향**)를 다시 계산한 뒤 쓰세요.
