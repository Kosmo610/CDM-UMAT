# EasyPBC V.1.4 로 우리 RVE의 주기경계조건을 점검하는 방법

대상 덱: `abaqus/ZHANG2022_*_V2_0.inp` (TexGen 평직 RVE, 3.5 × 3.5 × 0.44 mm,
34 049 절점 / 174 405 C3D4, PBC = `ConstraintsDriver0..5` + `*Equation`)

플러그인 원본: Omairey S., Dunning P., Sriramula S. (2018),
*Development of an ABAQUS plugin tool for periodic RVE homogenisation*,
Engineering with Computers. https://doi.org/10.1007/s00366-018-0616-4

---

## 1. 왜 쓰는가

우리 덱의 PBC는 TexGen이 자동 생성한 것을 그대로 쓰고 있다. 지금까지 이것이
"맞다"는 근거는 TexGen이 그렇게 뱉었다는 것뿐이다. EasyPBC는 **완전히 독립된
구현**으로 같은 메시에 PBC를 다시 깔아 주므로, 다음 세 가지를 독립 검증할 수 있다.

1. 메시가 실제로 절점 단위로 주기적인가 (대응면 절점이 1:1로 짝지어지는가)
2. 우리 `*Equation`이 올바른 주기성을 표현하는가
3. 균질화 강성 C̄ 와 열팽창 ᾱ 가 독립 구현에서도 같은 값이 나오는가

논문 3장(검증)에 넣을 수 있는 형태의 교차검증이다.

---

## 2. EasyPBC가 실제로 주는 정보

소스(`easypbc.py`, 2 220줄)를 직접 읽고 정리한 것이다.

### 2-1. 메시 주기성 진단 (← 이것이 "점검"의 본체)

세트 생성 단계에서 세 가지 검사를 하고, 실패하면 메시지 영역에 오류 번호를 찍고
문제 절점을 모아 어셈블리에 **`Error set`** 이라는 절점 집합으로 만들어 준다.
따라서 CAE에서 그 세트를 바로 하이라이트해서 눈으로 볼 수 있다.

| 오류 | 검사 내용 | 원인 |
|---|---|---|
| 06 | 마주보는 면/모서리 세트의 **절점 개수**가 같은가 | 메시가 비주기적이거나 `Mapping accuracy`가 너무 큼 |
| 07 | 모든 절점이 짝을 찾았는가 (`Error set` 생성) | 좌표 오차 > 허용치 |
| 08 | 한 절점이 **두 개 이상**과 짝지어지지 않았는가 | 허용치가 너무 커서 이웃 절점까지 매칭 |

3D에서는 **6개 면 + 12개 모서리 + 8개 꼭짓점**을 전부 분리해서 검사한다.
면만 맞고 모서리가 틀린 경우도 잡힌다.

### 2-2. 균질화 물성 (잡을 돌릴 경우)

| 출력 | 개수 | 산출 방식 |
|---|---|---|
| E11, E22, E33 | 3 | 잡 `job-E11/E22/E33` |
| ν12, ν13, ν21, ν23, ν31, ν32 | 6 | 위 3개 잡의 코너 절점 변위에서 부수적으로 |
| G12, G13, G23 | 3 | 잡 `job-G12/G13/G23` |
| CTE X, Y, Z | 3 | 잡 `job-CTE` (V1.4에서 추가, 3D 전용) |
| 총 질량, 균질화 밀도 | 2 | `getMassProperties()` / (L·H·W) |

파일 출력 두 개가 작업 디렉토리에 생긴다.

```
<모델명>_elastic_properties.txt            ← 표 형식 (사람이 읽는 용)
<모델명>_elastic_properties(easycopy).txt  ← 값만 한 줄씩 (엑셀 붙여넣기용)
```

그리고 `job-E11.odb` 등 **ODB를 지우지 않고 남긴다.** 변형 형상과 응력장을
직접 볼 수 있으므로, 면이 평면을 유지하지 않고 주기적으로 우글거리는지
(= PBC가 제대로 걸렸다는 시각적 증거) 확인할 수 있다.

### 2-3. PBC 자체 (Equation + 참조점)

`only PBC` 체크박스를 켜면 **잡을 하나도 돌리지 않고** 세트·참조점·`*Equation`만
만들고 끝난다. 우리 목적(주기경계조건 점검)에는 이 모드가 핵심이다.

## 3. 계산 원리 — 우리 덱과 무엇이 다른가

### 3-1. EasyPBC의 규약

면 이름은 전역축 기준으로 자동 분류된다.

| EasyPBC 세트 | 위치 |
|---|---|
| `fronts` / `backs` | x = x_max / x_min |
| `tops` / `bots` | y = y_max / y_min |
| `lefts` / `rights` | z = z_max / z_min |

수직(E) 하중용 구속식은 이렇다.

```
u_fronts,1 − u_backs,1 − RP4_1 = 0      (x)
u_tops,2   − u_bots,2   − RP5_2 = 0      (y)
u_lefts,3  − u_rights,3 − RP6_3 = 0      (z)
```

즉 **참조점의 자유도 값 = 변위 점프(mm)** 이다. 하중은 그 참조점에 변위로 준다
(`Disp = 0.2 × 변의 길이`, 즉 공칭 변형률 0.2). 그리고

```
σ = |ΣRF at RP| / (수직면 면적)        E11 = σ / (Dispx / L)
```

ν는 반대쪽 코너 두 개의 변위 차이로 변형된 변의 길이를 재서 구한다.
CTE는 `intemp → fntemp` 균일 온도장을 주고 코너 간 거리 변화로

```
CTE_X = ΔX / (L · ΔT)
```

### 3-2. 우리 덱의 규약 (TexGen)

```
FaceA,1 · 1.0 + FaceB,1 · (−1.0) + ConstraintsDriver0,1 · (−3.5) = 0
```

계수 −3.5 = −L 이므로 **드라이버 자유도 값 = 변형률 ε (무차원)** 이다.

### 3-3. 환산 (교차검증할 때 반드시 필요)

| | 드라이버 DOF의 의미 | 자유 드라이버 잔차의 물리적 의미 |
|---|---|---|
| 우리 덱 (변형률 드라이버) | ε | R = σ · **V**_RVE |
| EasyPBC (변위 드라이버) | Δu = ε·L | R = σ · **A** (해당 면 면적) |

```
ConstraintsDriver0_1  =  RP4_1 / L
```

`CLAUDE.md`의 "자유 드라이버 잔차는 곧 매크로 응력 오차 R = σV" 는 **우리 덱
형식에서만** 성립한다. EasyPBC 모델을 볼 때는 부피가 아니라 면적으로 나눠야 한다.
M1 디버깅 때 두 모델을 섞어 보면 3.5/0.44 배만큼 헷갈릴 수 있으니 주의.

## 4. 사전 점검 결과 (Abaqus 없이 미리 확인함)

`ZHANG2022_RT23_V2_0.inp`의 절점 좌표를 직접 읽어 대응면 매칭을 오프라인으로
검사했다. 결과:

| 면 쌍 | 절점 수 (min / max) | 면내 좌표 일치 | 중복 매칭 |
|---|---|---|---|
| x = −0.875 / 2.625 | 394 / 394 | 394/394 (오차 < 1e−9) | 0 |
| y = −0.875 / 2.625 | 406 / 406 | 406/406 (오차 < 1e−9) | 0 |
| z = −0.02 / 0.42 | 3 951 / 3 951 | 3 951/3 951 (오차 < 1e−9) | 0 |

**결론: 이 메시는 절점 단위로 정확히 주기적이다.** 좌표가 소수점 아래까지
완전히 일치하므로 `Mapping accuracy` 기본값 `10E-8`(=1e−7)을 그대로 써도
오류 06/07/08은 나지 않아야 한다. 만약 뜬다면 그것은 메시 문제가 아니라
**임포트 과정에서 좌표가 변질된 것**이므로 그쪽을 의심해야 한다.

메시를 새로 뽑으면 이 표는 무효다. `docs/MESH_STRATEGY.md`의 "`.ori`는 메시와
한 몸" 규칙과 같은 성격이다.

## 5. 설치

받은 zip 안의 두 폴더를 **Abaqus 작업 디렉토리**에 통째로 복사한다.

```
<작업디렉토리>\abaqus_plugins\EasyPBC V.1.4\   (easypbc.py, easyPBCDB.py, easyPBC_plugin.py, 아이콘)
<작업디렉토리>\abaqus_icons\                    (easypbc.png)
```

CAE를 재시작하면 상단 **Plug-ins → Elastic Properties Calculator (EasyPBC V.1.4)** 로 뜬다.

> **Windows 전용이다.** 소스가 `ctypes.windll.user32.MessageBoxA`와
> `path + '\job-E11.odb'` (역슬래시)를 쓴다. 리눅스 CAE에서는 오류 대화상자에서
> 죽는다. 우리는 Windows 워크스테이션이므로 문제 없다.

## 6. 사용 절차

### 6-0. 공통 — 오펀 메시를 CAE로 가져오기

우리 덱은 CAE 모델이 아니라 오펀 메시 `.inp`다. EasyPBC는
`mdb.models[...].rootAssembly.instances[...]`를 읽으므로 임포트가 필요하다.

1. `File → Import → Model...` 에서 `.inp` 선택
2. 생성된 모델의 파트/인스턴스 이름을 확인한다 (보통 `PART-1`, `PART-1-1`)
3. 인스턴스를 더블클릭해 새로고침한다 (노란 체크가 남아 있으면 오류 04)

EasyPBC는 어셈블리에 **인스턴스가 정확히 하나**여야 하고, 창에 적는
모델명·인스턴스명은 **대소문자까지 일치**해야 한다 (오류 02 / 03).

---

### 6-A. 모드 A — 주기경계조건만 점검 (권장, 해석 안 돌림)

플러그인 창에서:

| 항목 | 값 |
|---|---|
| Model name | 임포트된 모델 이름 |
| Instance name | 예: `PART-1-1` |
| Mesh mapping accuracy | `10E-8` (4절 근거) |
| Number of CPUs | 1 (잡을 안 돌리므로 의미 없음) |
| E11 / E22 / E33 | **체크** |
| G12 / G13 / G23 | **체크 해제** ← 아래 함정 참조 |
| CTE | 체크 해제 |
| only PBC | **체크** |

`OK` → 메시지 영역을 본다.

- 오류 06/07/08이 **하나도 없으면** 메시 주기성 통과.
- `Error set`이 생겼으면 CAE에서 그 세트를 표시해 어느 면이 깨졌는지 본다.

그다음 우리 덱과 대조하려면, 모델을 `.inp`로 써서 `*Equation` 블록을 비교한다.

```
Job → Create → (모델 선택) → Write Input
```

비교 포인트:
- 구속식 **개수**가 우리 덱과 같은 자릿수인가 (면·모서리·꼭짓점 모두 포함했는가)
- 각 식이 참조하는 자유도 조합이 3-1절 규약과 일치하는가
- 우리 덱의 `Edge*`/`Vertex*` 처리에 빠진 조합이 없는가

> **함정: `only PBC` 를 켠 상태에서 E와 G를 동시에 체크하지 마라.**
> 소스 1689–1692줄에서 전단(G) 구속식을 만들기 직전의 기존 구속 삭제 루프가
> `if onlyPBC == False:` 로 막혀 있다. 즉 `only PBC` + E + G를 함께 켜면
> **수직용 구속식과 전단용 구속식이 동시에 남아** 심하게 과구속된 모델이 나온다.
> 한 번에 한 종류씩 확인한다.

---

### 6-B. 모드 B — C̄ 와 ᾱ 를 독립 계산해서 교차검증

우리 4장의 균질화 결과(C̄, ᾱ)를 독립 구현으로 검증하는 용도다.
**단, 그대로는 안 된다.** 이유:

> **EasyPBC가 제출하는 모든 잡은 `userSubroutine=''` 이다.**
> (소스 438, 536, 668, 1378 … 줄) 즉 **UMAT이 붙지 않는다.**
> 우리 재료는 `*User Material`이므로 잡이 즉시 죽는다.

그리고 하중이 `0.2 × 변의 길이`, 즉 **공칭 변형률 0.2 (20 %)** 다. 선형탄성이면
E = σ/ε 이 크기와 무관하므로 문제없지만, 손상 모델이 붙으면 전부 파괴된다.
(G13/G23은 W = 0.44 mm 라서 형식상 전단변형률이 1.5를 넘는다 — 선형 해석이므로
수치적으로는 무해하나 물리적 의미는 없다.)

따라서 **탄성 쌍둥이 모델**을 만들어 돌린다.

1. 임포트한 모델을 복제한다
2. `Matrix`, `Yarn0..3` 재료를 `*User Material` 대신 다음으로 바꾼다
   - `*Elastic, type=ENGINEERING CONSTANTS` (얀은 횡등방 9상수, 매트릭스는 등방)
   - `*Expansion` (CTE를 뽑을 거면 필수)
   - `*Density` (질량·밀도 출력용, 선택)
   - 값은 `data/properties/eval_correlations.py`에서 나온 상관식 값을 쓴다
3. `*Orientation`(TexGen 방향)은 **반드시 유지**한다. 이게 빠지면 에러 없이
   섬유 방향이 틀린 채 수렴한다 — `CLAUDE.md`에 이미 적힌 그 함정이다
4. E11/E22/E33/G12/G13/G23 + CTE 전부 체크, `only PBC` **해제**
5. Number of CPUs: **10** 정도 (잡을 순차로 하나씩 돌린다. 32를 다 줘도
   Abaqus/Standard는 선형으로 안 빨라진다 — `CLAUDE.md` 코어 배분 원칙)

예상 시간: 지배적인 비용은 절점 매칭(O(N²) 파이썬 이중 루프)이 아니라 **CAE 커널
호출 횟수**다. EasyPBC는 경계 절점 **하나마다 어셈블리 세트를 하나씩**,
자유도마다 `Equation`을 하나씩 만든다. 174k 메시에서는 세트 약 9 500개 +
구속식 약 14 000개가 되어 **세트·구속 생성만 수십 분에서 한 시간대**를 잡아야 한다.
26k 메시(`M*_c26k_*`, 경계 절점 122/118/1037)는 세트 약 2 600개 +
구속식 약 3 800개라 몇 분이면 끝난다.

**26k 메시로 절차와 옵션을 먼저 확정하고, 174k는 최종값 산출에 한 번만 돌린다.**
26k 메시도 절점 주기성은 완전하다 (122/122, 118/118, 1037/1037, 중복 0).
선형탄성 잡 7개(E×3, G×3, CTE)는 잡당 1–3분이라 무시할 만하다.

판정 기준(제안): EasyPBC의 E11, E22, E33, G12, G13, G23, ν, ᾱ 가 우리 덱의
균질화 값과 **1 % 이내**면 두 PBC 구현이 동치라고 본다.

> **CTE 잡의 주의점.** CTE 블록(2006–2012줄)은 모든 하중과 경계조건을 지우고
> 온도장만 준다. 참조점이 전부 자유로워지므로 강체 이동이 구속되지 않아
> `.msg`에 numerical singularity 경고가 뜰 수 있다. 결과는 코너 간 **상대**
> 변위로 계산하므로 대개 유효하지만, `.msg`를 반드시 열어보고 경고가 3개
> (강체 병진 3개)를 넘지 않는지 확인한다. 넘으면 값을 쓰지 않는다.

## 7. 함정 요약

| 함정 | 결과 | 대처 |
|---|---|---|
| UMAT이 안 붙는다 (`userSubroutine=''`) | 잡 즉시 종료 | 모드 A를 쓰거나 탄성 쌍둥이 모델 |

| 기존 TexGen `*Equation` 잔존 | — | E 블록은 기존 constraint를 전부 지우므로 자동 정리됨. 단 `MasterNode1` 고정 BC는 남으니 의도적으로 둘지 결정할 것 |
| 리눅스에서 실행 | `ctypes.windll` 에서 죽음 | Windows에서만 |
| 메시 재생성 후 4절 표 재사용 | 잘못된 판단 | 메시 바뀌면 주기성 재확인 |

## 8. 논문에 어떻게 쓰는가

3장(검증)에 "주기경계조건 구현의 독립 검증" 항목으로 세 줄이 들어간다.
