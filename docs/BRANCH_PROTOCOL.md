# 두 채팅이 같이 일하는 방법 (2026-08-04 제정)

> **질문:** 문헌 브랜치에 논문을 올리면, 읽고 정리해서 해석 브랜치로 넘기고,
> 해석 브랜치에서 새 정보가 오면 그걸 받아 코드에 반영하는 구조로 갈 수 있나?
>
> **답: 됩니다. 그리고 이미 한 바퀴 돌았습니다.** 아래는 그 증거와, 돌려 보니
> 드러난 마찰 두 가지, 그리고 그것을 없애는 규칙입니다.

---

## 1. 이미 작동한 증거

두 채팅은 서로의 대화를 **못 봅니다.** 기억을 공유하지 않습니다.
**공유하는 것은 저장소 하나뿐이고, 그것으로 충분했습니다.**

```
문헌 브랜치            595e552  "코드 작업을 코드 채팅으로 넘김"
                          │        (HANDOFF_TO_CODE_CHAT.md 작성)
                          ├──────────────────► 해석 브랜치가 여기서 갈라져 나감
                          │                     ├ 551d7ae M6가 무엇을 보정할지 설계
                          │                     ├ a45733e 얀 Xt에 출처가 있었다
                          │                     ├ 012dca1 강성 격차는 공극률이었다
                          │                     ├ 75ff85e ◄── 문헌 브랜치를 병합
                          │                     └ 17b08a1 §4.9-16 규약으로 덱 관문
                          │
                          └ (문헌 브랜치는 계속 진행: 최신논문 조사, 카이저 판단…)
```

**확인된 것 셋:**

1. **인수인계가 읽혔습니다.** 제가 남긴 미결 1번(부호 인코딩)과 5번(카드 재생성)에
   저쪽이 **결론을 달아 같은 파일에 되돌려 놨습니다** — "부호 유지, 대신 소비 측에
   관문을 건다". 제 문서에 그 답이 적혀 있습니다.
2. **제 코드가 그대로 쓰였습니다.** §4.9-16(제가 §4.9-12로 만든 것)의 규약이
   `make_macro_thermalshock.py`의 관문이 되었습니다.
3. **되돌아온 정보가 제 결론을 뒤집었습니다** — 아래 §2.

**결론: 채팅 대 채팅이 아니라 저장소가 통신선입니다. 커밋이 메시지고, 병합이 배달입니다.**

## 2. 되돌아온 정보 — 제 판정 두 건이 틀렸습니다

이게 사용자가 원하는 **역방향**이 실제로 작동한 사례입니다.

### 2.1 얀 $X_t$ — 제 "IN(독립 근거 있음)" 판정이 틀렸습니다

`check_card_ranges.py`는 얀 $X_t$ = 2835 MPa를 **IN**(독립 근거 확인)으로 분류하고
있었습니다. 근거는 *"혼합칙 $V_f \times 3580$, T300 데이터시트 3530과 1.4 % 차"*.

**해석 브랜치가 `refs/[08]`(Sauder, Lamon & Pailler, CST 62 (2002) 499)을 읽었고,
그 Table 1은 T300 단섬유를 직접 측정합니다 — 24 °C에서 2107 MPa.**
카드의 3580은 **스트랜드(다발) 값**이고 단섬유 측정보다 1.70배 높습니다.

> **제가 놓친 이유는 명확합니다. `refs/[08]`은 저장소에 있는데 제가 안 읽었습니다.**
> 저는 "그 값이 자기 출처와 일치하는가"를 확인했지, **"측정 대상이 카드가 요구하는
> 대상과 같은가"** 를 확인하지 않았습니다. 다발 강도를 필라멘트 자리에 넣은 것입니다.

**조치:** 병합 시 `check_card_ranges.py`의 이 항목은 **저쪽 판정을 받습니다.**
IN 8개 중 하나가 빠지므로 **독립 근거 비율이 31 %에서 더 내려갑니다.** 정직한 방향입니다.

### 2.2 공극률 — 두 값이 어긋나고, 그 어긋남이 유용합니다

오늘 제가 §4.7.3에 [28]의 **10–15 %**를 넣었습니다. 저쪽은 밀도 역산으로 **19.6 %**를
얻었습니다. 같은 논문에서 나온 두 숫자입니다.

이쪽에서 독립 재계산한 결과 **[28]이 자기모순**입니다 — 적힌 밀도 2.0과 섬유율 40 %면
19.6 %가 나오고, 10–15 %가 되려면 밀도가 2.15–2.31이어야 합니다(7–15 % 차, 반올림
불가). **해석: 10–15 %는 열린 공극, 19.6 %는 총량.** 표면 50 µm 밀봉층이 이를 뒷받침합니다.

| 질문 | 값 |
|---|---|
| 열전도 (§4.7.3) | **총량 19.6 %** |
| 산화·$k$ 부호 (§2.5.4) | **열린 공극 10–15 %** |

§4.7.3과 `conductivity_bounds.py`(34항목)에 반영했습니다.

## 3. 마찰 두 가지 — 구조적이지 우연이 아닙니다

병합을 실제로 시도해 보니 **4개 파일이 충돌**했습니다. 원인이 분명합니다.

### 3.1 전역 카운터 충돌 (충돌 4건 전부 이것)

```
CLAUDE.md                              "커밋 전에 위 N개를 전부 통과시킨다"
docs/CH1_INTRODUCTION.md               "N개 항목이 매 커밋 전에…"
docs/CH3_VERIFICATION.md               검증 총량 표의 합계
verification/check_chapter_consistency.py   "automated verification item count"
```

**양쪽이 검증을 추가할 때마다 같은 숫자를 서로 다르게 고칩니다.** 내용 충돌이 아니라
**장부 충돌**이라, 매번 반드시 납니다.

> **규칙 A — 합계는 손으로 적지 않는다.** 총량은 스크립트가 **세게** 하고,
> 문서에는 자리표시자만 둔다. 그러면 병합 시 숫자가 다투지 않는다.
> (당장 고치려면 코드 채팅과 합의가 필요하므로, 그때까지는 **충돌 나면 양쪽 다
> 세어서 큰 쪽 + 새로 추가된 만큼**으로 손 해결한다.)

### 3.2 영역 경계가 지켜지지 않았습니다 — 그리고 그게 옳았습니다

제가 `HANDOFF_TO_CODE_CHAT.md` §6에 "`data/properties/*`는 문헌 쪽"이라고 그었는데,
저쪽이 거기에 **2095줄**을 썼습니다(`insitu_yarn_strength.py`, `porosity_stiffness.py`,
`m6_calibration.py`, `make_property_workbook.py`).

**규칙을 어긴 것이 아니라, 제 규칙이 틀렸습니다.** 물성 발견은 해석을 하다가 나오고,
문헌 발견은 코드를 짜다가 나옵니다. **파일로 영역을 나누는 것은 실패합니다.**

> **규칙 B — 파일이 아니라 "누가 최종 판정하는가"로 나눈다.**
>
> | 사안 | 최종 판정 | 다른 쪽이 하는 일 |
> |---|---|---|
> | 값의 **출처와 신뢰 등급** | **문헌** | 발견해서 넘김 |
> | 값이 **카드에 적법한가**(구성재 vs 복합재) | **문헌** | 필요를 제기 |
> | 값이 **코드에서 어떻게 쓰이는가** | **해석** | 제약을 알림 |
> | 수렴·솔버·덱·UMAT | **해석** | — |
> | 장별 본문의 **인용** | **문헌** | 수치 제공 |
>
> **어느 쪽이든 상대 영역의 파일을 고쳐도 된다.** 다만 **판정이 갈리면 위 표가
> 정한다.** §2.1이 그 예다 — 저쪽이 제 파일을 고쳤고, 판정은 제 쪽이지만
> **제 판정이 틀렸으므로 저쪽 값을 받습니다.**

## 4. 앞으로의 작업 흐름

### 4.1 사용자가 하는 일 (2단계뿐)

1. **논문 PDF를 `claude/paper-reference-research-pksw5p` 브랜치의 `refs/`에 업로드**
   (파일명 앞에 목록 번호: `S1 ...pdf`, `최신2 ...pdf`)
2. **"올렸어"** 라고 알려주기

### 4.2 문헌 채팅(이쪽)이 하는 일

1. 논문 신원 대조 (제목·저자·권·쪽) — **비슷한 제목의 다른 논문을 받는 실수가 흔함**
2. 전문 읽기 → 신뢰 등급 승급 (`abstract` → `fulltext`)
3. **숫자 추출 + 카드 적법성 판정** (구성재만 카드 입력 가능)
4. `check_card_ranges.py` 갱신 — IN / DEV / GUESS 재분류
5. **`docs/TO_ANALYSIS.md` 에 "코드가 알아야 할 것"만 적어 넘김**

### 4.3 해석 채팅이 하는 일

1. 그 값을 카드·덱에 반영
2. 해석 중 나온 물성·문헌 의문을 **`docs/TO_LITERATURE.md`** 에 적어 되돌림
3. 병합

### 4.4 넘김 문서 두 개의 형식

**`docs/TO_ANALYSIS.md`** (문헌 → 해석) 각 항목:

```
### [번호] 한 줄 제목
- 무엇이 바뀌나 : 카드 슬롯 / 파라미터 / 서술
- 옛 값 → 새 값 : (숫자와 단위)
- 출처         : refs/[NN] 표 N, 등급 fulltext
- 카드 적법성   : 구성재 ✔ / 복합재 ✘(검증 전용)
- 무효화되는 것 : 이 값으로 이미 돌린 해석이 있는가
- 검증         : 실행할 스크립트
```

**`docs/TO_LITERATURE.md`** (해석 → 문헌) 각 항목:

```
### [번호] 한 줄 질문
- 어디서 나왔나 : 어느 잡 / 어느 계산
- 무엇을 알고 싶나 : (구체적 양과 단위)
- 왜 급한가    : 이게 없으면 무엇이 막히는가
- 지금 쓰는 값  : 있으면 그 값과 근거
```

**두 파일 모두 "처리 완료" 항목은 지우지 않고 ✅ 표시만 한다.** 왜 그렇게 결정했는지가
나중에 필요해집니다 — §2.1이 그 예입니다.

## 5. 병합 규칙

- **한쪽이 큰 작업을 끝내면 즉시 병합한다.** 오래 두면 충돌이 커집니다.
  (지금 10 대 4 커밋으로 갈렸고, 충돌 4건입니다.)
- **병합 후 반드시 검증 전수 실행.** 양쪽 검증이 합쳐지므로 개수가 바뀝니다.
- **충돌은 전부 §3.1의 장부 충돌일 것으로 예상됩니다.** 내용 충돌이 나면
  그건 **판정이 갈린 것**이므로 §3.2 표로 해결합니다.
